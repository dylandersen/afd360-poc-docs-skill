## How to add a release entry

<Callout type="warn" title="Don't skip this">
A change log nobody updates is worse than no change log — it implies stability that
isn't there.
</Callout>

1. Move the relevant items from **Unreleased** into a new dated section above v0.1.0.
2. Use semver: bump **patch** for fixes, **minor** for backward-compatible additions,
   **major** when you change behavior the customer integrated against.
3. Tag the commit: `git tag v0.2.0 && git push --tags`.
4. Announce per the [Rollout Plan → Communications plan](/docs/rollout-plan#communications-plan)
   if the change is user-visible.
